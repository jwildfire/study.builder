A clinical trial's data, simulated in your browser

study.builder makes a whole synthetic study, from raw data to ADaM tables, site metrics and reports, and lets you look through all of it. R runs in this page, so nothing is installed and nothing is sent anywhere. Every row is made up: no real participant or site is in it.

  1. Portfolio The list below. Open a ready-made study at once, or build one from its settings.
  2. Study view One study, looked through: an overview, the schedule and design when it follows a protocol, an efficacy score by arm, every table of every layer, and one participant at a time. Pick a monthly snapshot to see the study as it stood then.
  3. Study builder Describe your own under New study: its size, a CDISC protocol to follow, the layers and domains to make. The first build takes about half a minute.

New here? Open CDISC pilot protocol below and press through its tabs. To use a study in your own page or package, see Use it from another page and the README.

Use it from another page

One script defines StudyBuilder. Draw the builder in an element and take the study when the reader hands it over, or build a study with no page at all. 

<script src="https://jwildfire.github.io/study.builder/study.builder.js"></script>
<div id="builder"></div>
<script>
  // The builder on your page. `study.files()` is { raw, standard }: each a list of { name, text }.
  StudyBuilder.mount('#builder', {
    onStudy(study) {
      const { raw, standard } = study.files();
      myApp.loadRaw(raw);
      myApp.loadFiles(standard);
    }
  });

  // Or no page at all: settings in, data out.
  const study = await StudyBuilder.buildStudy({
    participants: 200,
    sites: 15,
    months: 6,
    domains: ['AE', 'LB', 'VS']
  });
  study.domains.find((domain) => domain.id === 'AE').text; // the CSV text
</script>
Everything runs in this browser. Nothing is sent anywhere. Data is simulated by gsm.datasim.
